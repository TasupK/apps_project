# Phase 5: Streamlit UI & Demo

**기간:** 5~6주차  
**담당:** 팀원 A+D  
**상태:** 완료
**목표:** 전체 프로세스를 시각적으로 확인하고 발표에서 안정적으로 시연할 수 있는 Streamlit 대시보드를 완성한다.

## 핵심 역할

Phase 5는 팀의 결과물을 사용자가 이해할 수 있는 형태로 보여준다. 화면은 단순 장식이 아니라 AI의 판단 근거를 사람이 검증하는 작업 공간이어야 한다.

## 작업 범위

- `buybee.db` 기반 재고 리스크 대시보드 구현
- 부족 자재 및 부족 수량 표시
- 선택한 부족 자재에 대해 실제 Phase 2 웹 검색 후보 수집 실행
- 후보별 출처, 가격, 납기, 출처 준비도 표시
- Fastener 카테고리는 Phase 3 평가 리포트까지 생성
- 판단 근거, 스펙 차이, 리스크 메모, 출처 URL 표시
- 채팅형 Human-in-the-loop 승인/반려 UI 구현
- 승인 전 `PO_Result.csv` 생성 차단
- 승인 시 `PO_Result.csv` 생성 및 화면 표시
- 발표용 반복 데모 흐름 정리

## 화면 구성

| 영역 | 내용 |
|---|---|
| 상단 | 선택 자재, 카테고리, 부족 수량, 승인 상태 |
| 좌측 상단 | DB 재고 현황, 안전재고 대비 현재고, 부족 자재 테이블 |
| 좌측 중앙 | 실제 웹 리서치 실행 결과와 부족 자재 스펙 |
| 좌측 하단 | 후보별 가격, 납기, 출처 신뢰도, 리스크 메모, 출처 URL |
| 우측 | AI Personal Assistant 채팅형 승인 창 |
| 결과 | 승인 후 `PO_Result.csv` PO 초안 테이블 |

## 사용자 흐름

```text
재고 확인해줘
-> 부족 자재 감지
-> 대체품 찾아줘
-> 실제 웹 검색 후보/신뢰도/리스크 확인
-> 승인 또는 반려
-> 승인 시 PO_Result.csv 생성
```

## 발표 데모 스크립트

1. 앱 실행 후 좌측 재고 리스크 차트에서 DB의 부족 자재 상태를 보여준다.
2. 우측 승인 창에 `재고 확인해줘`를 입력해 부족 수량을 확인한다.
3. `대체품 찾아줘`를 입력해 SerpAPI 기반 실제 웹 검색 후보를 수집한다.
4. 후보별 출처, 가격, 납기, URL, 리스크 근거를 설명한다.
5. `승인`을 입력해 Human-in-the-loop 이후에만 `PO_Result.csv`가 생성되는 것을 보여준다.
6. 필요하면 `상태 초기화` 버튼으로 같은 흐름을 반복한다.

## 실행 가이드

```bash
pip install -r requirements.txt

# 선택: 상세 추출/LLM 쿼리 생성 사용 시
export OPENAI_API_KEY="..."
streamlit run streamlit_hybrid_app.py
```
