# Phase 5: Streamlit UI & Demo

**기간:** 5~6주차  
**담당:** 팀원 A+D  
**목표:** 전체 프로세스를 시각적으로 확인하고 발표에서 안정적으로 시연할 수 있는 Streamlit 대시보드를 완성한다.

## 핵심 역할

Phase 5는 팀의 결과물을 사용자가 이해할 수 있는 형태로 보여준다. 화면은 단순 장식이 아니라 AI의 판단 근거를 사람이 검증하는 작업 공간이어야 한다.

## 작업 범위

- 재고 리스크 대시보드 구현
- 부족 자재 알림 표시
- 웹 검색 후보 비교표 표시
- 기술 호환성/출처 신뢰도/최종 점수 표시
- 리스크 메모와 출처 URL 표시
- 승인/반려 UI 구현
- 승인 시 `PO_Result.csv` 생성 결과 표시
- 데모 시나리오와 발표 흐름 정리

## 화면 구성

| 영역 | 내용 |
|---|---|
| 상단/좌측 | 재고 현황, 안전재고 대비 현재고 |
| 중앙 | 결품 자재와 대체 후보 스펙 비교 |
| 하단 | 후보별 가격, 납기, 신뢰도, 리스크 메모 |
| 우측 | AI Personal Assistant 채팅형 승인 창 |
| 결과 | 승인 후 PO 초안 테이블 |

## 사용자 흐름

```text
재고 확인해줘
-> 부족 자재 감지
-> 대체품 찾아줘
-> 후보/신뢰도/리스크 확인
-> 승인 또는 반려
-> 승인 시 PO_Result.csv 생성
```

## 완료 기준

- 앱 첫 화면에서 재고 부족 상태를 확인할 수 있다.
- 대체 후보가 최소 2개 이상 비교표에 표시된다.
- 기술 호환성과 출처 신뢰도가 함께 보인다.
- 사용자가 승인하기 전에는 PO 초안이 생성되지 않는다.
- 승인 후 `PO_Result.csv`가 생성되고 화면에 표시된다.
- 발표자가 같은 순서로 반복 시연할 수 있다.

## 테스트 체크리스트

- `재고 확인해줘` 입력 시 부족 자재 메시지가 나오는가?
- `대체품 찾아줘` 입력 시 후보 비교표가 표시되는가?
- 후보별 URL, 가격, 납기, 신뢰도, 리스크 메모가 보이는가?
- 바로 `승인`을 입력했을 때 승인 대기 전이면 차단되는가?
- 승인 후 PO 결과가 생성되고 화면에 보이는가?
